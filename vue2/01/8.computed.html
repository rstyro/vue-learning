🎯 computed 与 watch 的区别

💡 一句话：computed 算东西（派生数据），watch 做事情（监听变化执行操作）。
  • computed：根据已有数据「推导」出新数据，自动缓存，依赖不变就不重算
  • watch：监听某个数据，变化时执行一段逻辑（副作用）
  • 能只用 computed 解决的，优先用 computed；需要做「事情」才用 watch

① computed 计算属性：全名自动拼接

姓：

名：

直接拼接：{{ firstName }} {{ lastName }}

computed 全名：{{ fullName }}

📌 模板里直接拼和 computed 效果一样，但逻辑复杂时（如拼接+截断+格式化）computed 更清晰、可复用、有缓存。

computed: {
    fullName: function () {
        // 依赖 firstName 和 lastName，任一变化自动重新计算
        return this.firstName + ' ' + this.lastName;
    }
}

② computed 实战：购物车总价（依赖多个数据）

商品单价数量小计
{{ item.name }} ￥{{ item.price }} {{ item.quantity }} ￥{{ item.price * item.quantity }}

商品总数：{{ totalCount }} 件

合计金额：￥{{ totalPrice }}

💡 totalCount 和 totalPrice 都是 computed：购物车数据一变，它们自动更新。
这比在模板里写一大串 reduce 表达式优雅得多，而且带缓存。

③ watch 侦听器：统计修改次数

姓：

名：

全名：{{ fullName2 }}

修改全名的次数：{{ count }} 次

watch: {
    fullName2: function (newVal, oldVal) {
        // 只要全名变化就执行（newVal 新值 / oldVal 旧值）
        this.count++;
    }
}

💡 和 computed 的区别：computed 是「派生数据给模板用」，watch 是「数据变了我要去做点事」（比如发请求、存草稿、写日志）。

④ watch 深度监听对象（deep）

配置：

配置变化日志：

  • {{ log }}
// 监听对象内部属性变化，必须加 deep: true（否则只监听引用替换）
watch: {
    config: {
        handler: function (val) { this.configLogs.unshift('配置变了: ' + val.theme); },
        deep: true
    }
}
