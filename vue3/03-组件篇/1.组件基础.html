🎯 为什么需要组件？

💡 组件 = 可复用的 UI 代码块。把页面拆成一个个小积木，每个积木负责自己的部分，拼起来就是完整页面。
  • 好处 1：复用（同一个按钮组件用 100 次，只写 1 次代码）
  • 好处 2：维护（改一个组件，所有用到它的地方都更新）
  • 好处 3：隔离（组件之间互不干扰，各管各的数据）

📖 组件间通信的两大核心：props（父→子）和 emit（子→父）

👨‍👩‍👧 父组件
⬇ props 传数据
🧒 子组件
⬆ emit 发事件
👨‍👩‍👧 父组件

💡 一句话：props 是父给子的「数据通道」，emit 是子给父的「消息通道」。
props 只能父→子单向传；子不能直接改 props，只能通过 emit 通知父组件去改（这叫「单向数据流」）。

② 组件定义源码详解

// 定义子组件（在实际项目中，每个组件是一个独立的 .vue 文件）
const MessageItem = {
    template: `
        <div :class="{ read }">
            <h4>{{ title }}</h4>
            <p>作者：{{ author }}</p>
            <button @click="$emit('toggle-read')">标为已读</button>
            <button @click="$emit('delete')">删除</button>
        </div>`,
    props: ['title', 'author', 'read'],  // 声明接收哪些数据（父传子）
    emits: ['toggle-read', 'delete'],       // 声明向外发哪些事件（子传父）
};

// 父组件中使用
createApp({
    components: { MessageItem },           // 注册子组件
    setup() {
        const messages = ref([...]);
        function removeMessage(id) { ... }  // 接收子组件 emit 的事件
        return { messages, removeMessage };
    }
}).mount('#app');
⚠️ props 只读原则：子组件里改 props（比如 props.read = true）会报警告且无效。
✅ 正确做法：子组件 emit('toggle-read')，让父组件去改数据（数据改完父组件自动把新值通过 props 传回来）。

③ props 进阶：类型校验与默认值

💡 props 写成「对象」形式可以校验类型、设默认值、标必填——团队协作时非常有用，写错立刻有警告。

props: {
    title:   { type: String,  required: true },          // 必填字符串
    author:  { type: String,  default: '匿名' },          // 可选，默认'匿名'
    read:    { type: Boolean, default: false },           // 可选，默认 false
    size:    { type: [String, Number], default: 'md' },   // 多种类型
    config:  { type: Object,  default: () => ({}) },      // 对象默认值必须用函数返回
}

④ 思考题（看答案前先想想）

1️⃣ 如果子组件需要把「自己内部的数据」传给父组件，该用什么？
  → emit('事件名', 数据)，父组件用 @事件名="函数(数据)" 接收。

2️⃣ 如果父组件改了 props 值，子组件会自动更新吗？
  → 会！props 是响应式的，父数据一变，子组件自动重渲染。

3️⃣ 组件上绑定的普通属性（没在 props 里声明）会怎样？
  → 会自动成为组件的「根元素属性」（Attribute Inheritance），后面课程会提到。
