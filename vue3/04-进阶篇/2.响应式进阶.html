🎯 本课内容：深入理解 Vue 3 的响应式系统

💡 除了 ref / reactive / computed / watch，Vue 3 还提供了一批「进阶响应式 API」，用于解决特定场景：
  • toRefs / toRef：保住 reactive 解构后的响应性
  • readonly：创建只读数据（防止别人改）
  • shallowRef：浅层响应（性能优化）
  • customRef：完全自定义响应式行为
  • isRef / isReactive：类型判断

① toRefs：reactive 解构不丢响应性的钥匙

reactive 解构演示

原始对象 user：{{ user.name }}（{{ user.age }} 岁）

解构出的 name：{{ name }}

toRefs 解构出的 age：{{ age }}

💡 上面的 name 是普通解构（不响应），age 是 toRefs 解构（响应）。
  • 普通解构 { name } = user → name 是普通字符串，改了不更新原始对象
  • toRefs 解构 { age } = toRefs(user) → age 是 ref，改它会同步改 user.age
  📌 常见场景：reactive 的 state 传给子组件前，先用 toRefs 保住响应性

const user = reactive({ name: '张三', age: 18 });

// ❌ 普通解构：name 变成普通字符串，和 user.name 断开连接
const { name } = user;
name = '李四';   // user.name 不变！

// ✅ toRefs 解构：每个属性变成 ref，仍然连着原始对象
const { age } = toRefs(user);
age.value = 20;  // user.age 变成 20！

② readonly：把数据变成「只读」

readonly 演示

原对象 user2：{{ user2.name }}（可修改）

只读副本 readonlyUser：{{ readonlyUser.name }}

⚠️ 点「尝试修改」后按 F12 打开控制台，会看到 Vue 的警告：
Set operation on key "name" failed: target is readonly

💡 readonly 的典型用途：给子组件传「只读配置」，防止子组件误改；
或者把响应式数据导出给外部时不想被意外修改。

④ customRef：自定义响应式行为（防抖搜索实战）

customRef 防抖输入

显示的值：{{ debouncedText }}

💡 原理：customRef 让你完全掌控「什么时候触发更新」。
这里做了 300ms 防抖：停止输入 300ms 后，内容才真正更新到页面上（常用于搜索框）。

// 自定义 ref：带防抖功能
function useDebouncedRef(value, delay = 300) {
    let timeout;
    return customRef((track, trigger) => {
        return {
            get() {
                track();          // 收集依赖
                return value;
            },
            set(newValue) {
                value = newValue;
                // 防抖：每次设置都清除上一个定时器
                clearTimeout(timeout);
                timeout = setTimeout(() => trigger(), delay);  // 延迟触发更新
            }
        };
    });
}

⑤ 类型判断 API 速查

isRef(x) —— 判断是不是 ref
isReactive(x) —— 判断是不是 reactive 创建的代理对象
isReadonly(x) —— 判断是不是 readonly
isProxy(x) —— 判断是不是任何代理对象（reactive/readonly 都算）
shallowReactive(x) —— reactive 的浅层版本
toRaw(x) —— 拿到被代理包装前的「原始对象」
